# 01 · 核心玩法

> 本文档定义《Agamemnon 竞拍之王》的核心游戏循环与胜负判定规则。

---

## 一、游戏概述

### 1.1 定位

《Agamemnon 竞拍之王》是一款 **4 人竞技拍卖游戏**，玩家通过估算仓库价值来争夺排位分。

**核心创新**：
- ❌ 金币**不是**资源（金币无限）
- ✅ **估值精度**决定胜负
- ✅ 信息不对称创造策略深度
- ✅ 分段倍率机制创造心理博弈

### 1.2 一局时长

| 环节 | 时长 |
|------|------|
| 选英雄 | 30s |
| 选天赋 | 30s |
| 5~10 个回合 | ~60s/回合 |
| 赛后结算 | 30s |
| **总计** | **约 8~12 分钟** |

### 1.3 玩家配置

| 项目 | 数值 |
|------|------|
| 每局玩家数 | 4 |
| 单机 Demo | 1 人类 + 3 AI |
| 联机版 | 4 人类（含可选 AI 填补） |

```
  ┌──────────────────────────────────────┐
  │           匹配 4 位玩家               │
  └──────────────┬───────────────────────┘
                 ↓
  ┌──────────────────────────────────────┐
  │    英雄选择 (30s)                     │
  │    每人选 1 个英雄（影响揭露方式）     │
  └──────────────┬───────────────────────┘
                 ↓
  ┌──────────────────────────────────────┐
  │    天赋选择 (30s)                     │

                 ↓
  ┌──────────────────────────────────────┐
  │    生成仓库（所有玩家看同一个仓库）    │

                 ↓
  ┌──────────────────────────────────────┐
  │         赛后排位结算                   │
  └──────────────────────────────────────┘
```

## 三、单回合详细流程

### 3.1 单回合阶段图

```
  ┌─────────────────┐
  │ 回合开始 (1s)    │ 显示 "第 N 回合"
  │                 │ 显示当前倍率 R(N)
  └────────┬────────┘
           ↓
  ┌─────────────────┐
  │ 揭露阶段 (30s)   │ - 英雄被动自动触发
  │                 │ - 天赋效果生效
  │                 │ - 玩家使用主动技能
  │                 │ - 查看已揭露物品
  └────────┬────────┘
           ↓
  ┌─────────────────┐
  │ 出价阶段 (20s)   │ - 密封出价（看不到他人）
  │                 │ - 可选择弃拍（出 0）
  │                 │ - 倒计时结束自动提交
  └────────┬────────┘
           ↓
  ┌─────────────────┐
  │ 判定阶段 (5s)    │ 比较出价，应用回合倍率
  │                 │ 判断是否有人拍下
  └────────┬────────┘
           ↓
      ┌────┴────┐
      ↓         ↓
   拍卖成功   流拍
      │         │
      ↓         ↓
  ┌─────────────────┐
  │ 结算阶段 (10s)   │
  │ - 拍成→公布真值  │ - 流拍→进入下一回合
  │ - 计算分数变动   │
  │ - 公开各方出价   │
  └─────────────────┘
           ↓
  ┌─────────────────┐
  │ 进入下一回合     │ 或结束本局
  └─────────────────┘
```

|------|------|---------|
| 回合开始 | 1s | 观看横幅 |
| 揭露阶段 | 30s | 使用技能/查看面板 |
| 出价阶段 | 20s | 输入出价金额 |
| 判定阶段 | 5s | 观看 |
| 结算阶段 | 10s | 观看结算动画 |
| **单回合合计** | **~66s** | |

## 四、回合倍率机制 ⭐ 核心

### 4.1 倍率表（10 回合版）

| 回合 | 倍率 R(N) | 判定规则 | 设计意图 |
|------|-----------|---------|---------|
| 第 1 回合 | **2.0** | 最高价 ≥ 次高价 × 2.0 | 信息极少，想抢必须砸大价 |
| 第 2 回合 | **1.6** | 最高价 ≥ 次高价 × 1.6 | 信息略多，门槛下降 |
| 第 3 回合 | **1.3** | 最高价 ≥ 次高价 × 1.3 | 中期博弈 |
| 第 4 回合 | **1.1** | 最高价 ≥ 次高价 × 1.1 | 临界点 |
| 第 5 回合 | **1.0+** | 最高价 > 次高价（严格大于） | 正常拍卖门槛 |
| 第 6 回合 | **1.0+** | 最高价 > 次高价 | 加时赛开始 |
| 第 7 回合 | **1.0+** | 最高价 > 次高价 | |
| 第 8 回合 | **1.0+** | 最高价 > 次高价 | |
| 第 9 回合 | **1.0+** | 最高价 > 次高价 | |
| 第 10 回合 | **1.0+** | 最高价 > 次高价（最终局） | |

### 4.2 判定流程

```
假设 4 人出价排序：P1 ≥ P2 ≥ P3 ≥ P4
回合 N 的倍率：R(N)

  ┌─────────────────────────────┐
  │ IF P1 ≥ P2 × R(N):           │
  │   ✅ 拍卖成功                 │
  │   → 最高价玩家获得仓库        │
  │   → 进入结算阶段              │
  │   → 本局结束                  │
  │                              │
  │ ELSE:                        │
  │   ❌ 流拍                     │
  │   → 无人获得仓库              │
  │   → IF N < 10: 进入下一回合   │
  │   → IF N = 10: 本局全流拍     │
  └─────────────────────────────┘
```

### 4.3 特殊情况

#### 情况 1：全员弃拍（所有人出价 0）
```
P1 = P2 = P3 = P4 = 0
→ 自动流拍
→ 进入下一回合
```

#### 情况 2：最高价并列
```
P1 = P2（两人出价相同最高）
→ 视为"未严格大于次高价"
→ 流拍，进入下一回合
→ 鼓励玩家出"非整数"避免碰撞
```

#### 情况 3：10 回合全流拍
```
前 10 回合都没人拍下
→ 本局结束
→ ⭐ 所有人排位分 0 变动（友好型）
→ 算作"情报不足的和局"
```

### 4.4 倍率机制的博弈空间

**前期砸价派（激进）**：
- 第 1 回合直接砸一个超高价，赌其他人都保守
- 风险：信息少，估值可能严重偏差
- 收益：如果真值高，一把大赚

**中期等待派（稳健）**：
- 前 2~3 回合保守出价，等信息累积
- 在第 3~5 回合看准了再动手
- 最常见的玩家策略

**后期消耗派（保守）**：
- 前期故意低价或弃拍
- 等揭露信息足够多，第 5~10 回合再发力
- 风险：可能被激进派提前抢走
- 收益：估值最准

## 五、密封出价机制

### 5.1 出价规则

- **密封**：玩家输入金额后，**其他人看不到**
- **无限金币**：出价上限 = 无穷（实际可限制 10 亿防溢出）
- **精度**：出价为整数（避免浮点误差）
- **可弃拍**：出 0 视为弃拍

### 5.2 出价时机

- 20 秒倒计时结束时自动提交
- 可以提前确认（不提前公布，仍然保密）
- 未输入 = 默认弃拍（出 0）

### 5.3 反作弊考虑

- **客户端不记录他人出价**（防止内存查看）
- **服务器端密封**：收到所有出价后才开始判定（联机版）
- **单机 Demo**：AI 不读取玩家出价，独立决策

## 六、胜负与排位

### 6.1 单局内的输赢

一局游戏里，**4 人的排位分变动总和为 0**（零和博弈）：
- 拍下者若估值准确 → 上分
- 拍下者若估值偏差大 → 掉分
- 其他 3 人按反向等比变动

详细公式见 [`02_scoring.md`](./02_scoring.md)。

### 6.2 本局结束条件

**以下任一条件触发本局结束**：
1. ✅ 任何一回合中有玩家成功拍下仓库（满足倍率要求）
2. ✅ 第 10 回合结束仍无人拍下 → 全流拍和局

### 6.3 持续玩法

- 一局结束后 → 赛后结算页面（显示分数变动、段位变动）
- 可再次匹配 → 新仓库、新英雄选择

## 七、玩家行动自由度

### 7.1 揭露阶段能做什么

| 操作 | 频率 | 说明 |
|------|------|------|
| 查看已揭露物品 | 无限 | 鼠标悬浮查看 tooltip |
| 使用主动技能 | 受 CD 限制 | 每个英雄 1 个主动 |
| 使用消耗品（线索卡） | 有数量限制 | 初期简化，后期扩展 |
| 查看对手状态 | 无限 | 只能看到对方"状态"（思考中/已出价），不能看具体信息 |
| 提前进入出价阶段 | 无 | 必须等倒计时 |

### 7.2 出价阶段能做什么

| 操作 | 说明 |
|------|------|
| 输入金额 | 整数，可大可小 |
| 修改金额 | 倒计时结束前可改 |
| 提前确认 | 确认后不可更改 |
| 弃拍 | 留空或输入 0 |
| 查看自己的估值辅助 | UI 可显示"已揭露价值 / 揭露率 / 推算总价" |

### 7.3 不允许的操作

- ❌ 看其他玩家的具体信息
- ❌ 看其他玩家的出价
- ❌ 交流（Demo 阶段无聊天系统）
- ❌ 回看历史回合（需要时通过 UI 日志查看简要信息）

## 八、玩法示例（完整演示）

### 8.1 理想胜局案例

```
【第 1 回合】倍率 2.0
- 玩家A（占卜师）：揭露到 2 个紫色物品 → 估值 25000
  出价 28000（激进）
- 玩家B：揭露到 1 个绿物品 → 估值 15000
  出价 14000
- 玩家C：揭露到 1 个白物品 → 估值 10000
  出价 9000
- 玩家D：弃拍 → 出 0

判定：P1=28000, P2=14000, P1/P2=2.0 ≥ 2.0 ✅
→ A 拍下

结算：真实价值 V = 30000
→ A 的偏差 = (30000-28000)/30000 = +6.67% (捡漏)
→ A 获得 +2 分
→ BCD 各 -0.67 分
```

### 8.2 前期流拍案例

```
【第 1 回合】倍率 2.0
- 四人出价：P1=15000, P2=12000, P3=10000, P4=0
- P1/P2 = 1.25 < 2.0 ❌
→ 流拍

【第 2 回合】倍率 1.6（信息累积了一回合）
- 四人出价：P1=20000, P2=18000, P3=15000, P4=5000
- P1/P2 = 1.11 < 1.6 ❌
→ 流拍

【第 3 回合】倍率 1.3
- 四人出价：P1=25000, P2=19000, P3=16000, P4=10000
- P1/P2 = 1.32 ≥ 1.3 ✅
→ 拍下，进入结算
```

### 8.3 极端和局案例

```
四位玩家都非常保守 / 估值都不准
→ 10 个回合都没人敢出高价
→ 10 回合后全流拍
→ 所有人 0 分变动
→ 系统提示："本局信息不足，排位分未变动"
```

## 九、设计原则回顾

1. **估值精度 > 金币数量**：无限金币让玩家专注估值能力
2. **前高后低的倍率**：前期信息少、后期信息多，对应倍率递减
3. **10 回合上限**：给保守玩家足够时间，但不无限拖延
4. **友好流拍**：和局不惩罚，避免"必须出价"的压力
5. **零和排位**：4 人分数变动总和为 0，纯技术对抗

# 03 · 仓库与物品系统

> 本文档定义《Agamemnon》的仓库结构、物品尺寸与品质体系。

---

## 一、仓库（Warehouse）

### 1.1 基本属性

| 属性 | 数值 |
|------|------|
| 仓库网格 | **10 列 × 200 行 = 2000 格** |
| 单格尺寸 | 50 × 50 像素 |
| 面板总尺寸 | 500 × 10000 像素（可滚动） |
| 单个仓库的物品数 | 50 ~ 300 件（视物品尺寸分布而定） |
| 单个仓库的真实总价值 | 5,000 ~ 500,000（差异巨大） |

### 1.2 视觉参考

```
┌─────────── 10 列 ──────────────┐
│ [D][D][A][B][B][B][E][F][F][G] │ 1
│ [D][D][A][B][B][B][E][F][F][G] │ 2
│ [D][D][A][B][B][B][E][F][F][G] │ 3
│ [H][H][H][H][I][I][J][J][K][L] │ 4
│ [H][H][H][H][I][I][J][J][K][L] │ 5
│ [M][N][O][P][Q][R][S][T][U][V] │ 6
│ [M][N][O][P][Q][R][S][T][U][V] │ 7
│        ...  200 行 ...         │
└────────────────────────────────┘

A, B, ... = 不同物品，B 是一个 3×3 的大件
D 是一个 2×3 的中件
H 是一个 4×2 的横向长件
M~V 是一排 1×1 小件
```

**视觉风格**：类似游戏中的"杂物堆""背包格""货架"，物品紧密相邻排列。

### 1.3 仓库生成规则

```
生成算法（伪代码）：
1. 初始化 10×200 的空网格
2. 从顶部到底部，逐行扫描空格
3. 对每个空格：
   a. 随机决定物品尺寸（权重偏向小件）
   b. 检查是否能放下（不越界、不重叠）
   c. 放不下则缩小尺寸，直到 1×1
   d. 放置物品，标记覆盖的所有格子
4. 继续下一个空格，直到网格填满
5. 物品紧密相邻，无空格
```

### 1.4 仓库类型（差异化）

为提升重玩性，设计多种仓库"风格"：

| 仓库类型 | 特征 | 估值难度 |
|---------|------|---------|
| **均匀仓** | 品质均匀分布，无集群 | 简单，揭露少数格即可外推 |
| **聚集仓** | 高品质物品集中在某几行 | 困难，没揭到好货区血亏 |
| **大件仓** | 多个 4×4 以上的大件 | 中等，大件定总价 |
| **杂货仓** | 几乎全是 1×1 小件 | 困难，量大但单价低 |
| **宝藏仓** | 总价高，但含少量大红物 | 极难，揭没揭到红物差别巨大 |
| **陷阱仓** | 看起来花花绿绿其实低价值 | 极难，容易高估 |

**实现**：每个仓库有一个"类型标签"，影响生成算法的权重参数。

### 1.5 玩家视角

**所有玩家看到同一个仓库**（同一局游戏）：
- 仓库的物品分布 = 公共信息（但盲区遮盖了内容）
- 揭露 = 获取**自己能看到**的那部分信息
- 不同玩家看到的"已揭露内容"不同 → 信息不对称

## 二、物品系统

### 2.1 物品尺寸

支持 **1×1 到 6×6** 的任意矩形尺寸：

```
尺寸       示例      出现频率
─────────────────────────────
1×1        小玉石     ~40%
1×2 / 2×1  卷轴       ~15%
2×2        花瓶       ~15%
2×3 / 3×2  画卷       ~10%
3×3        古琴       ~8%
3×4 / 4×3  地毯       ~5%
4×4        大型雕塑    ~3%
4×5 / 5×4  屏风       ~2%
5×5        大型家具    ~1.5%
5×6 / 6×5  巨型挂毯    ~0.5%
6×6        史诗级藏品  ~0.1%
```

### 2.2 尺寸与价值的关联

```
物品真实价值 ≈ base_value × (宽 × 高) × quality_multiplier

        × 随机扰动 (0.7 ~ 1.3)

其中：
  base_value    = 20 (基础小件价值)
  quality_multiplier = 品质系数（见 2.3）
```

**所以**：
- 同品质下，**大件物品价值远高于小件**
- 揭露到大件 → 估值的"锚点"更清晰
- 大件 = 高价值靶子，也是英雄技能的重点目标

### 2.3 物品品质

| 品质 | 颜色编码 | 品质系数 | 占比 | 价值档次 |
|------|---------|---------|------|---------|
| ⬜ 白 | #CCCCCC | 1.0 | 45% | 普通 |
| 🟢 绿 | #4ADE80 | 2.5 | 25% | 优良 |
| 🔵 蓝 | #3B82F6 | 6.0 | 15% | 精良 |
| 🟣 紫 | #A855F7 | 15.0 | 10% | 史诗 |
| 🟡 黄 | #FBBF24 | 40.0 | 4% | 传说 |
| 🔴 红 | #EF4444 | 100.0 | 1% | 神话 |

### 2.4 具体价值计算示例

```
示例 1：1×1 白色物品
  价值 = 20 × 1 × 1.0 × [0.7~1.3] = 14 ~ 26

示例 2：3×3 紫色物品
  价值 = 20 × 9 × 15.0 × [0.7~1.3] = 1,890 ~ 3,510

示例 3：6×6 红色物品
  价值 = 20 × 36 × 100.0 × [0.7~1.3] = 50,400 ~ 93,600

示例 4：4×4 蓝色物品
  价值 = 20 × 16 × 6.0 × [0.7~1.3] = 1,344 ~ 2,496
```

### 2.5 物品数据结构

```
Item {
  id:              唯一 ID
  name:            中文名称（如 "东陵玉鳄石"）
  name_en:         英文名称（本地化）
  size:            (width, height)  如 (2, 3)
  quality:         品质枚举
  true_value:      真实价值（生成时计算）
  icon:            图标资源路径
  silhouette:      轮廓资源（黑色剪影）
  category:        类别（武器/家具/艺术品/书籍/消耗品...）
}
```

### 2.6 物品类别（Category）

物品有 **类别** 标签，用于"轮廓揭露"层级：

| 类别 | 示例 | 轮廓特征 |
|------|------|---------|
| 🗡️ 武器 | 剑、刀、枪 | 细长尖锐 |
| 🛡️ 防具 | 盔甲、盾牌 | 规整厚重 |
| 🖼️ 艺术 | 画、雕塑、挂毯 | 方形/曲线 |
| 🏺 器皿 | 花瓶、茶具、碗碟 | 圆润 |
| 📖 书籍 | 古籍、卷轴 | 长方条 |
| 💎 饰品 | 玉石、首饰、珠宝 | 小而亮 |
| 🪑 家具 | 椅子、桌子、屏风 | 大体积 |
| 🧪 消耗 | 药水、食物、烟具 | 瓶装小件 |

**揭露"轮廓"时**：显示该类别的黑色剪影，玩家可推测价值但不精确。

## 三、仓库总价值估算

### 3.1 理想玩家估值方式

```
1. 统计已揭露物品的真实价值总和 known_value
2. 统计已揭露格子数 revealed_cells
3. 揭露率 = revealed_cells / 2000
4. 估算总价 = known_value / 揭露率
5. 根据仓库类型的先验知识微调
6. 考虑回合倍率要求，决定出价
```

### 3.2 估算难点

**难点 1：分布不均**
- 揭到的区域不能代表整个仓库
- 10 行里揭的都是白绿物品，但 50 行外可能埋着红物
- **应对策略**：通过英雄技能揭露分散区域

**难点 2：大件信息不完整**
- 揭到一个 4×4 物品的一角 ≠ 揭到整个物品
- 玩家要判断"这是整件还是部分"

**难点 3：类别误判**
- 看到"方形轮廓"可能是画也可能是书
- 画和书的价值系数相差很大（同品质下艺术品 × 1.2，书籍 × 0.9）

### 3.3 估值辅助 UI（可选）

在出价阶段，系统可以显示辅助信息（基于已揭露）：

```
┌─────────────────────────────┐
│ 估值辅助                     │
├─────────────────────────────┤
│ 已揭露格子：  120 / 2000    │
│ 揭露率：      6.0%          │
│ 已知物品：    18 件         │
│ 已知总价值：  3,200         │
│                             │
│ 线性推算总价：~53,333       │
│ 按仓库类型调整：~48,000     │
│                             │
│ ⚠ 揭露率较低，估值不确定性高│
└─────────────────────────────┘
```

**注意**：这只是辅助，不是答案。高段位玩家会无视这个推算，用自己的直觉。

## 四、物品池（Item Pool）

### 4.1 物品池设计

需要准备一个**物品库**，包含：
- ~500 个基础物品模板（Demo 阶段 100 个够用）
- 每个物品有固定的：名称、尺寸、类别、图标
- 品质和真实价值在**仓库生成时随机**（同一物品在不同仓库可能是白色也可能是紫色）

### 4.2 物品命名规则（中文主）

```
示例：
  [白绿] 青铜镜 / 木梳 / 铜钱
  [蓝]   青花瓷 / 翡翠镯 / 古籍
  [紫]   鎏金佛 / 白玉观音 / 宋瓷碗
  [黄]   元代青花 / 王羲之书法拓本
  [红]   商周青铜鼎 / 唐三彩马 / 乾隆官窑

命名模式：
  [朝代 / 材质 / 工艺] + [物品类型]
  如 "明代" + "景泰蓝" + "香炉"
```

### 4.3 物品池分层

| 层级 | 数量 | 品质倾向 |
|------|------|---------|
| 基础层（常见） | 300+ | 白/绿为主 |
| 中级层 | 150+ | 蓝/紫为主 |
| 高级层 | 40+ | 黄为主 |
| 传说层 | 10+ | 红专属 |

**生成逻辑**：
- 白/绿品质 → 从基础层抽取
- 红品质 → 从传说层抽取
- 防止"一个锈铜镜显示红色品质"的违和感

## 五、仓库生成算法（伪代码）

```python
def generate_warehouse(type="均匀仓"):
    grid = Array[10][200] filled with None
    items = []

    # 尺寸权重（参考 2.1）
    size_weights = {
      (1,1): 40, (1,2): 7, (2,1): 8, (2,2): 15,
      (2,3): 5, (3,2): 5, (3,3): 8, (3,4): 2.5,
      (4,3): 2.5, (4,4): 3, (4,5): 1, (5,4): 1,
      (5,5): 1.5, (5,6): 0.25, (6,5): 0.25, (6,6): 0.1
    }

    # 根据仓库类型调整权重
    if type == "大件仓":
        # 增加大尺寸权重
        adjust_weights_for_large(size_weights)

    # 扫描填充
    for row in 0..199:
        for col in 0..9:
            if grid[row][col] is None:
                size = weighted_random(size_weights)
                # 尝试放置，放不下则缩小
                actual_size = try_place(grid, row, col, size)

                # 决定品质
                quality = weighted_random(quality_weights)
                # 从物品池抽取匹配尺寸和品质的物品
                item_template = pick_item(actual_size, quality)
                # 计算真实价值
                true_value = calculate_value(item_template, actual_size, quality)

                item = Item(template, actual_size, quality, true_value)
                items.append(item)
                fill_grid(grid, row, col, actual_size, item)

    return Warehouse(grid, items, type)
```

## 六、Demo 阶段简化

**Demo 阶段的仓库系统**：

### ✅ 保留
- 10 × 200 网格
- 1×1 ~ 4×4 的尺寸（先不做 5×5 和 6×6）
- 6 种品质
- 一种仓库类型（均匀仓）
- 20~30 个基础物品模板
- 总价值计算

### ❌ 暂不做
- 多种仓库类型
- 100+ 物品池
- 类别系统（可以全部按"通用物品"）
- 仓库主题皮肤
- 复杂的外观渲染（用彩色方块 + 品质边框即可）
